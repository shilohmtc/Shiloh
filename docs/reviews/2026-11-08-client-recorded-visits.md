# Client recorded-visit summary

Approved feature behavior; implementation and release evidence are recorded in its pull request.

Client → Overview describes recorded attendance linked to the current canonical profile, within the viewer’s existing clinic/private scope. Completed and no-charge outcomes count only after the appointment ends; payment, cancellations and no-shows do not establish attendance. Linked treatments count once per client; guest profiles remain separate. No names, mobiles or organiser contacts bridge legacy identities. Last recorded visit uses available linked history; counts and most-received treatment use the trailing 12 calendar months in Africa/Johannesburg. Missing treatment detail and tied leaders are explicit, rather than an inferred favourite. These are recorded-history summaries, not lifetime coverage or retention cohorts.

A usual interval requires four distinct visit dates. It uses the median positive calendar-day gap only when at least 75% of gaps are within 50% of the median and no gap exceeds twice it; otherwise intervals are described as variable. The range remains visible. Sparse history makes no rhythm claim. Independent same-day bookings remain separate visits but cannot create zero-day intervals. The existing scoped batch supports at most 24 clients, with a read-only transaction, acquisition/statement/lock limits and a 5,000-appointment per-client cap. Ambiguous cross-day linked groups, exceeded limits or read failures show unavailable rather than fabricated figures. Existing appointment links remain the review path. No client/financial writes, profile merging, new permission or schema migration are part of this feature. The Directory now shows only compact appointment dates; the separate [Client Insights page](2026-11-08-client-insights.md) carries the aggregate period view. Individual Overview details remain unchanged.
